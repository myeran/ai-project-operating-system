# החלטה ארכיטקטונית — כניסה מקוצרת מסשן Codex

## מטרה

לאפשר למשתמש לפתוח את המאגר ב־Codex, לכתוב משפט טבעי אחד על התחלת פרויקט,
ולהתחיל את הזרימה בלי לפתוח את Local Chat בדפדפן.

## מצב קיים

- `project-navigator` הוא שכבת השיחה וההנחיה.
- `runtime/runtime_api.py` הוא מקור האמת לפעולות הפרויקט.
- `launcher/start.sh` מפעיל את Runtime API, MCP ו־Local Chat.
- `runtime/local_client.py` הוא לקוח מקומי קיים ל־Runtime API.

## החלטה

להרחיב את נקודת הכניסה הקיימת בלבד:

1. ה־launcher יקבל `--no-browser` ויישאר idempotent.
2. ה־Skill יזהה בקשת התחלה טבעית ויפעיל את ה־launcher רק אם ה־Runtime אינו זמין.
3. נתוני ההתחלה יישלחו דרך `runtime/local_client.py` אל Runtime API הקיים.
4. ה־Runtime ימשיך להיות הבעלים היחיד של Project State, Registry והשלבים.

## גבולות ואינווריאנטים

- אין יצירת מסד נתונים או Project State נוסף.
- אין פתיחת דפדפן במסלול Codex.
- אין המצאת שם, מטרה או תוצאה; נתונים חסרים נאספים מהמשתמש.
- ההפעלה חוזרת ובטוחה: אם השירותים פעילים, לא נוצרים תהליכים כפולים.
- כל החלטה או מעבר שלב ממשיכים לדרוש אישור משתמש לפי החוזים הקיימים.

## אפשרויות שנדחו

- `KEEP`: Local Chat נשאר זמין למשתמשים שמעדיפים דפדפן.
- `MERGE`: מסלול Codex משתמש ב־Runtime API הקיים.
- `DEFER`: חיבור MCP native ישיר ל־Codex, משום שה־launcher והלקוח המקומי
  מספקים כרגע גבול יציב ופשוט יותר.

## תנאי סגירה

- בדיקות Runtime עוברות.
- `--no-browser` מפעיל את השירותים ללא `open`.
- בקשת התחלה טבעית מתועדת ב־Skill ובמדריך.
